# Canonical Operational Entity Model

An operational entity is a durable, inspectable object participating in state, relationships or evidence. Initial kinds: `SITE`, `PIT`, `FRONT`, `LOADING_UNIT`, `TRUCK`, `ROUTE`, `DESTINATION`, `SERVICE_LOCATION`, `OPERATOR`. Add kinds only when a real contract requires them.

## Identity

- Internal ID: immutable UUID/ULID generated by NORTHMINE; never derived from display label.
- Natural scope key: `(tenant_id, site_id, source_system, entity_kind, external_id)` unique over active identity records.
- External identifiers are typed aliases with `source_system`, `external_id`, validity interval and provenance.
- Display name, equipment number and operator name are mutable attributes, not identity.
- Tenant/site are mandatory for operational entities; cross-site aliases require explicit mapping, not string equality.
- Type is part of the source identity to prevent a truck and shovel both named `03` colliding.

Merging aliases requires an auditable identity-resolution record; source evidence retains the original external identifier. Deactivation closes validity but does not delete history. Operators require privacy/RBAC handling distinct from equipment.

Minimal record: `entity_id`, tenant/site, kind, canonical label, active flag, aliases, `effective_from/to`, provenance, created/updated timestamps. No generic entity-attribute-value abstraction is approved.
